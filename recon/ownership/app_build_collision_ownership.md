# CPUAPP retain-all collision ownership

`app_build_collision_ownership.json` converts the 151 strong-symbol collisions
from the CPUAPP retain-all shell into per-VA, fail-closed ownership decisions.
It is generated by `tools/build_app_collision_ownership.py` from the real linker
diagnostics and an index of the exact objects selected by that build.

A same-name collision is evidence that the configured build selected an SDK
owner, but it is not sufficient evidence that the firmware VA has been named
correctly or that the shell selected the firmware's Kconfig variant.  The
catalog therefore requires all of the following before exclusion:

- a selected, globally bound object definition;
- a unique indexed owner and a DWARF function signature;
- opcode-sequence score of at least 0.90;
- operand-shape score of at least 0.70; and
- instruction-count ratio of at least 0.80.

The first pass promoted 58 functions and retained 93.  A second real link then
reported exactly those 93 retained symbols and no promoted symbol, proving that
the generated source selection behaved as predicted.  The two link-log hashes,
the exact collision-set comparison, source hashes, source repository commits,
ABI records, object/section provenance, scores, and blockers are recorded in
the JSON catalog.

The retained set is intentional evidence, not unfinished mechanical work.  It
contains clear stale-name or configuration mismatches.  For example, the
firmware function currently called `crc16_reflect` has 138 bytes and a 0.314
opcode score against Zephyr's 42-byte `crc16_reflect`; excluding it merely
because the public names collide would silently remove different behavior.

Regeneration example (run from `/tmp` because the repository has a local
`struct.py`):

```sh
PYTHONSAFEPATH=1 /Users/freedomcoder/Projects/G1disasm2/.venv/bin/python \
  /Users/freedomcoder/Projects/G1disasm2/tools/build_app_collision_ownership.py \
  --link-log /tmp/g1_app_link.log \
  --index /tmp/g1_app_shell_upstream_index.json \
  --config /tmp/g1_cpuapp_build/zephyr/.config \
  --relink-log /tmp/g1_app_link_after_adoption.log
```

The adoption manifest consumes only rows where `safe_to_exclude` is true.  No
weak definition, `--allow-multiple-definition`, canonical-body edit, or symbol
override is used.
