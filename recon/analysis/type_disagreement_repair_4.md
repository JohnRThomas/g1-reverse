### 1.2 Blocker 1 removed — the SDK's parameter types put in scope

`hdrprobe.py` measures which minimal header defines each blocking type, with a
**positive control**: with no header at all every type must fail.

| type | minimal header | no-header control |
|---|---|---|
| `size_t`, `ptrdiff_t` | `<stddef.h>` | fails ✔ |
| `uint32_t` … | `<stdint.h>` | fails ✔ |
| `FILE` | `<stdio.h>` | fails ✔ |

and by a handful of symbols: `k_msgq_put` 29, `k_msgq_get` 18,

`k_sem_take` 4, `k_mem_slab_alloc` 4, `k_work_schedule` 3.

Every one of those takes a **`k_timeout_t`** — an 8-byte struct that AAPCS
passes in an *aligned core-register pair* on this target.

### 2.1 The shipped image says our code is ABI-CORRECT and source-WRONG

`att_req_sent` (`FUN_000822fc`), shipped bytes, `bl` to `k_work_reschedule`
(`FUN_0007350c`):

```
0008230e  mov.w    r2, #0xf0000
00082312  movs     r3, #0
00082314  add.w    r0, r0, #0x160
00082318  bl       #0x7350c            ; k_work_reschedule
```

r0 = the `k_work_delayable *`, **r2:r3 = the 64-bit `ticks`**, and **r1 is never
written for this call**. That is exactly
`k_work_reschedule(struct k_work_delayable *, k_timeout_t)`.

Our reconstruction spells it `void k_work_reschedule(unsigned int, unsigned int,
unsigned int, unsigned int)` and passes four arguments. Ghidra modelled the
register pair as two separate 32-bit parameters and modelled the *incidental*
r1 as a third. **The registers the callee reads are identical**; only the source
spelling is wrong. This is the same failure mode as calibration bug 6, seen from
the other side.

(Our object does emit one instruction the shipped image does not — `mov r1, r4`
at offset 0x14, the wasted r1 setup — and loads `0xf0000` from a literal pool as
`&rodata_f0000` instead of `mov.w r2, #0xf0000`. Both are recorded, neither is
repaired here.)

## 6. Stage 07's dead functions — the brief's question, answered

*"Check whether any of the 120 recovered functions Stage 07 found provably dead
are dead because a caller lost an argument or a whole call."*

**A lost argument cannot make a callee dead**, so the question reduces to lost
*calls*. The list exists only in a build log, so the stage-07 tree was built
**read-only** into `/private/tmp/g1-td4-s07` (nothing under `recon/refactor`
was written): `-Wunused-function` fires **118** times, 118 distinct names, 114
of which resolve to an image address.

### 6.1 The name-based test is worthless here — measured, not assumed

Intersecting the 118 names with the lost-call populations by NAME gives **0**.
By ADDRESS it gives **16**. The difference is entirely the alias confound pass 3
documented, and it cuts both ways:

```
by name    dead & (never called | called fewer times) :  0
by address dead & (never called | called fewer times) : 16
```

Three distinct provenance forms have to be resolved before the count means
anything, and the third is one pass 3 did not name:

1. the `NAME <= FUN_xxxxxxxx @ 0xADDR` block — pass 3's fix;
2. calls inside `#define` bodies (scan the raw text, not the blanked text) —
   pass 3's fix;
3. **the symbolizer's inline `/*=0xADDR*/` marker on the declaration itself.**
   Without it `get_addr_space_limit_1m` looks lost, when in fact
   `is_regular_addr_valid.c` calls it under the local name
   `nrfx_nvmc_flash_size_get`.

Resolving all three: of the 114 addressable dead functions, our tree **does**
call 43 (under some name) and calls **71** nowhere at all. Of the 16 leads, **2
dissolve** (`get_addr_space_limit_1m` via form 3, `libc_putc_buffered` from
`libc_write_buffer_via_putc.c`) and **14 survive**.

### 6.2 The 14, with their shipped callers

|---|---|---|
| `bt_uuid_expand_to_128` | `bt_uuid_cmp` | no |
| `cpu_idle_wfi_gate_check` | `arch_cpu_atomic_idle`, `arch_cpu_idle` | no |
